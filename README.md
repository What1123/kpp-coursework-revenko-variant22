## Опис проєкту

Клієнт-серверна система для автосервісу: облік клієнтів, їхніх автомобілів, сервісних замовлень і виконаних робіт.
Основні сутності: `Client` (клієнт), `Car` (автомобіль), `ServiceOrder` (сервісне замовлення), `Work` (робота).
Для кожного замовлення система автоматично обчислює інтегральний показник пріоритету
`I = 0,40·F1 + 0,35·F2 + 0,25·F3` і веде замовлення через чотири стани життєвого циклу:
`CREATED → DIAGNOSED → REPAIR → COMPLETED`.
Автомобілі можна імпортувати з CSV-файла у фоновому режимі, з індикацією ходу виконання.

Маршрут обробки запиту: `JavaFX → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL`.
Предметна валідація і робота з базою даних виконуються на сервері; клієнт лише відображає дані й передає запити.

## Підготовка бази даних MySQL

1. Запустити MySQL у XAMPP (модуль MySQL у XAMPP Control Panel).
2. Відкрити phpMyAdmin (`http://localhost/phpmyadmin`), вкладка «SQL» (або «Імпорт»).
3. Виконати вміст файла `database.sql` (або імпортувати файл). Скрипт видаляє наявну базу `car_service` і створює її заново з таблицями та початковими даними, тому не запускайте його на базі, дані якої потрібно зберегти.
4. Перевірити, що в базі `car_service` є таблиці `client`, `car`, `service_order`, `work`.
5. Параметри підключення задано в `server/src/main/java/ua/edu/nupp/kpp/server/DBUtil.java`
   (`jdbc:mysql://localhost:3306/car_service`, користувач `root`).
   Якщо на вашому комп'ютері для MySQL задано пароль, вкажіть його лише локально і не публікуйте у GitHub.

## Складання й запуск сервера

```bash
cd server
mvn clean test
mvn clean package
```

Після команди `package` створюється файл `server/target/car-service-server.war`.

1. Скопіювати `server/target/car-service-server.war` у каталог `webapps` встановленого Apache Tomcat 9.
2. Запустити Tomcat (`bin/startup.bat` у Windows, `bin/startup.sh` у Linux/macOS).
3. Перевірити роботу сервера у браузері: `http://localhost:8080/car-service-server/clients` — відповідь містить JSON зі списком клієнтів.

Інші адреси: `/cars`, `/orders`, `/works` (той самий префікс `http://localhost:8080/car-service-server`).

## Запуск JavaFX-клієнта

Перед запуском мають працювати MySQL і Tomcat із розгорнутим WAR-файлом.

```bash
cd client
mvn javafx:run
```

Клієнт має вкладки «Клієнти», «Автомобілі», «Сервісні замовлення» та «Роботи».
Адреса сервера за замовчуванням: `http://localhost:8080/car-service-server`.

## Запуск тестів JUnit 5

```bash
cd server
mvn clean test
```

Для виконання тестів не потрібні JavaFX, Tomcat і робоча база MySQL.
У проєкті 12 модульних тестів (`CourseworkTest`), які перевіряють:

- обчислення чинників F1 і F3 та інтегрального показника (контрольні значення: F3 = 8,75 і I = 52,19 для замовлення 1);
- відхилення недопустимих значень чинників (понад 100);
- дозволені переходи життєвого циклу (`CREATED → DIAGNOSED`, `DIAGNOSED → REPAIR`, `REPAIR → COMPLETED`);
- заборонений перехід (`CREATED → COMPLETED`);
- предметну валідацію клієнта, автомобіля і роботи.

Фактичні значення `Tests run`, `Failures`, `Errors`, `Skipped` і `BUILD SUCCESS` дивіться у виводі Maven.

## Імпорт автомобілів із CSV-файла

### Формат файла

Файли розташовані в `client/sample-data/`. Вимоги:

- кодування UTF-8, роздільник полів — крапка з комою `;`;
- перший рядок — заголовок із точно такими назвами й порядком стовпців;
- кожен наступний рядок — один автомобіль із 7 полів.

```
client_id;vin;license_plate;brand;model;production_year;mileage_km
2;WF0DXXGCBDGK12345;BI3456EE;Ford;Focus;2016;121400
```

| Поле | Тип | Правило (перевіряє сервер) |
|---|---|---|
| `client_id` | ціле число | клієнт із таким ідентифікатором має існувати в базі |
| `vin` | текст | 17 символів: великі латинські літери (без I, O, Q) і цифри; унікальний |
| `license_plate` | текст | до 15 символів; унікальний |
| `brand`, `model` | текст | не порожні, до 60 символів |
| `production_year` | ціле число | від 1950 до поточного року + 1 |
| `mileage_km` | ціле число | не від'ємне |

Клієнт перевіряє лише форму запису (заголовок, кількість полів, непорожні значення, числові типи).
Предметні правила перевіряє сервер.

### Як виконати імпорт

1. Запустити MySQL, Tomcat і JavaFX-клієнт.
2. Відкрити вкладку «Автомобілі».
3. У полі шляху вказати файл (за замовчуванням `sample-data/cars.csv`; шлях відраховується від каталогу `client`, з якого запущено `mvn javafx:run`).
4. Натиснути «Імпортувати CSV».
5. Імпорт виконується у фоновому потоці (JavaFX `Task`): ProgressBar показує хід виконання, поруч відображається поточний стан, а кнопка імпорту блокується до завершення.
6. Після завершення таблиця автомобілів оновлюється, а підсумок показує кількість імпортованих, пропущених і відхилених сервером рядків.

Події імпорту (початок, завершення, пропущені рядки та причини помилок) записуються в журнал `java.util.logging`.

### Повторний імпорт і дублікати

Сервер перевіряє унікальність VIN і державного номера. Тому повторний імпорт того самого файла
не створює дублікатів: усі рядки буде відхилено сервером як такі, що вже існують.
Файл `cars.csv` розрахований на базу, створену скриптом `database.sql`, до першого імпорту.

### Файл із помилками

Файл `cars-with-errors.csv` призначений для перевірки обробки помилок.
На чистій базі він дає: 1 імпортований запис, 3 рядки пропущено клієнтом
(неправильна кількість полів, нечислове значення року, порожній обов'язковий стовпець)
і 2 рядки відхилено сервером (VIN уже існує, клієнта не знайдено).
Помилка в окремому рядку не зупиняє імпорт; недоступність сервера зупиняє його з повідомленням про помилку.
